# Приёмка в Roblox Studio

Эта среда не запускала Studio. Команды ниже выполняют уже написанные диагностические модули; не объявляйте их пройденными до получения результатов из Studio.

Откройте отдельный закрытый тестовый place, включите доступ Studio к API только для тестовой experience, запустите Play. В Command Bar выберите контекст **Server**:

```lua
require(game.ServerScriptService.TouchlineServer.StudioQA).run({storage=true})
```

Модуль проверит жизненный цикл на настоящем Luau. При наличии API запишет/перезагрузит только отрицательный тестовый ключ `u-900000001` в `TouchlineDynasty_TEST_v2`. При временном memory-fallback покажет NOT RUN, а не PASS реального DataStore. В опубликованном сервере модуль откажется запускаться.

Для профиля клиента переключите Command Bar на **Client**, после загрузки карьеры запустите:

```lua
require(game.ReplicatedStorage.TouchlineShared.Diagnostics).run(60, {deviceLabel="укажите реальную модель устройства"})
```

Играйте обычный сценарий в течение замера. Из Output сохраните строку TOUCHLINE_CLIENT_QA: frame time p50/p95, память до/после, число PlayerGui Instances, разрешение/тип ввода, доступные показатели сетевой статистики. Сеть здесь общая для клиента, не изолированная по Touchline. Неподдерживаемые показатели остаются отсутствующими, не подменяются нулём. Для 30 минут реального времени используйте 1800 вместо 60. Это потребует настоящих 30 минут, а не ускоренной симуляции.

Оба диагностических модуля запрещают live-запуск. Они не тестируют успешную оплату, репликацию двух игроков, соответствие цен или качество управления. Отдельно пройдите RELEASE_CHECKLIST_RU.md и сохраните реальные скриншоты. Макеты не выдавайте за Studio.
